# 14 图示索引

这张表把仓库里能直接看的图登记成一份清单：从图号查到文件，从文件查到它说明什么。表里只有图号、内容、所在章节、文件路径和一句说明，不放结论，也不放形容词——结论在正文对应章节里。

## 14.1 怎么读这张表

- **图号用「章-序」**。`03-1` 是第 3 章第 1 张图，与正文里「图 03-1」的编号一致，可以直接对。正文没有嵌入、但仓库里可用的图，按它归属的章编号；主视觉与海报归第 1 章，因为它们服务于「项目是什么」这个第 1 章的问题。
- **所在章节**指这张图服务于正文哪一章，不是它物理上存放在哪，也不等于正文引用了它。括号里注明「已嵌入」或「正文未引用」；整套正文只有第 3 章用 Markdown 图片语法嵌入了图，其余行是仓库里可用、正文未嵌入的图。文件路径相对仓库根目录，`docs/图示索引.md` 本身在 `docs/` 下。
- **说明列只写看得见的东西**：图里有哪些信号、多少拍、多少像素。图的读法（比如某一拍为什么是那个值）在正文里。
- 表里既有图片，也有几份文本形式的波形摘要（`.txt` / `.json` / `.vcd`）。它们不是图片，但承担「图的说明书」作用，所以一并登记，并在说明列标出文件类型。

## 14.4 图从哪来

第 3 章的 8 张图不是截图，是脚本渲染的。链路是：用例 `stage1/1.3-vadd/cases/vadd_wave.c` 只发一条 `vadd.vv` → Verilator 带 trace 跑出 VCD → `scripts/61-extract-stages.sh` 调 `cases/vadd_stage_extract.py` 抽出 68 列 × 109 拍的逐拍表 `raw/vadd_stages.tsv` → `cases/wave_render.py` 从 61 列（分站图）与 12 列（总览图）的精简表渲染成 PNG。所以图上的每一格都能回到表里的一个数，表里的每一格都能回到 VCD 的一个时间戳。

06-1 到 06-6 那一组是另一条链路：`vdot_wave_20261105T091811.vcd`（131 MB，sha256 `ef0a6fdb…`）经体检脚本输出摘要与 JSON，再抽出 49 个关键信号成 14 KB 的窄窗摘录。摘录的拍号不重新编号，沿用源 VCD 的拍号，便于回查。原始 `.vcd.gz`（17 MB）也在同目录，需要看全量时解压它。

同目录有两套件，本表登记的是后一套。2026-11-05 那次作业产出 `vdot_wave_20261105T091811.key.vcd`、`.health.json`、`vcd-summary-20261105T091811.txt` 等，回读校验记 `checked=9648`；探针改了别名映射后对同一源 VCD 重算，得到 `…probefix-20261106.*` 一套，校验记 `checked=9849/9849`。两套都是真实产物，来自同一份源 VCD：第一套的摘录 14,156 B、回读比对计 9648 次，第二套 14,474 B、比对计 9849/9849。附录 A 的 §11.3 表 11-3 引的是第一套的文件名；本表登记 `probefix` 一套，因为它的判定多一条「有值信号必须全覆盖」。
