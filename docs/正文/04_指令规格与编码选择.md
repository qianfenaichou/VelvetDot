# 04 指令规格与编码选择

`vdot.vv` 把两个向量寄存器低 64 位里的 8 对 int8 相乘再求和，结果写进目的寄存器的低 32 位。规格要先定三件事：内部多宽、高位怎么写、`vl` 与 `vstart` 算不算限制；编码则要先证明没有占用别人的编号。这一章给出这些结论和证据，并逐条标出哪些来自赛题、哪些是本项目的决定。

## 4.1 一条指令算什么

指令写作 `vdot.vv vd, vs2, vs1`，属于 OPMVV 组（向量整数乘加类指令所在的译码组），不带掩码。int8 指 8 位有符号整数，取值范围 −128 到 127。源操作数只取 vs1 与 vs2 的低 64 位，从中取出字节 0 到 7 这 8 对；下文把每个字节位置叫一个 lane，高 64 位不参与运算。

设 `sum_wo[i] = sext8(vs1[i]) × sext8(vs2[i])`，其中 sext8 表示把 8 位按有符号解释。结果 `S = Σ_{i=0..7} sext19(sum_wo[i])`，每个积先符号扩展到 19 位再入树，不做零扩展。

旧 vd 不是输入。译码把「读旧 vd」的使能关掉，本指令不进 isMacc，也不登记到需要读旧 vd 的指令清单（vmaInsts）。因此 `vd` 与 vs1/vs2 编号重合时，源在写回前读取，按写后读语义处理。

## 4.2 内部为什么是 19 位

做法是先取两个最坏端点各算一遍，再与候选位宽的上限比一次。

最坏正和出现在 8 个 lane 全取 −128 乘 −128：8×(−128)×(−128)=131072。最坏负和出现在 −128 乘 127：8×(−128)×127=−130048。18 位有符号的上限是 131071，比 131072 少 1，装不下最坏正和。19 位有符号的范围是 [−262144, 262143]，两端都容得下。归约树（把 8 个乘积两两压缩求和的一组加法电路）因此按 19 位有符号设计。

19 位只影响内部树。宽度一旦不足，写回的 32 位结果就会错：18 位会把 131072 绕成负数，这个值原样出现在低 32 位才算对。风险因此落在内部树与边界用例上，第 7 章 §7.1 用最坏正和的字面常量盯住它。

## 4.3 写回契约

写回是 `vd[31:0] = sext32(S)`、`vd[127:32] = 0`。高 96 位恒清零，与 vta、vma 和 tail 都无关。指令是全写：不论 `vl` 取什么，128 位都写满。清零由数据通路直接给出，不依赖 Mgu（香山向量后端里处理 tail 与掩码写回策略的模块），因为 Mgu 在 tail 未激活时保留旧 vd，在 agnostic 时写全 1，两者都不是 0。

`vxsat` 不被改写，也不置位，保持执行前的值；执行前后用 `csrr vxsat` 读回同一个值。它是 sticky 位，预置成 1 时读回还是 1，不是恒为 0，细节见第 6 章 §6.3。正常执行后 `mstatus.VS` 置 Dirty。非法路径的 VS 只记录实测值，不预设「不变」。

## 4.4 什么情况算非法，vl 与 vstart 怎么处理

合法需要六条必要条件同时成立：SEW=8、LMUL=1、vm=1、`vstart=0`、vill=0、`mstatus.VS≠OFF`。任一条不成立即判非法。判定放在译码层，因为 Mgu 输出的 illegal 恒为 false。判定顺序上，先判非法，再处理 `vl=0` 的全写。

vill 这一条要单独说。非法 vsetvl 会把 vsew 与 vlmul 字段清 0 并置 vill=1，两个字段为 0 恰好对应 SEW=8、LMUL=1，前两条因此照常成立，只能靠 vill 位拦下。NEMU 把 vtype 写成 `1<<63`（`vcommon.c:114-117`），RTL 置 `vtype.illegal` 并清这四个字段（`Vsetu.scala:124-128`）。

`vl` 不参与结果计算。取 0 与取 1–7 一样，都算 lane 0–7 并写满 vd。这是对 RVV 的有意偏离：RVV 规范规定归约类指令在 `vl=0` 时不更新目的寄存器，本指令按赛题伪代码里无条件的 `for i in range(8)` 执行。NEMU 侧因此禁用 `check_vstart_ignore`，它在 `vstart≥vl` 时跳过写回，`vl=0` 时正好把这条语义改掉。

`vstart≠0` 直接判非法，正常执行路径上 vstart 恒为 0。这一项沿用既有的 `vstartIllegal`（`VecExceptionGen.scala:280`），但异常生成器并非没有改动：X14 在其中新增了 vdot 的 SEW/LMUL 谓词并并入 `illegalInst`（1 file +7/−1）。

## 4.5 编码三元组与机器码

编码由三元组加 vm 位固定：opcode `1010111`（OP-V）、funct3 `010`（OPMVV）、funct6 `001110`（0x0E）、vm=1。掩码版（vm=0）不在规格内，译码按非法处理。表 04-1 把示例 `vdot.vv v3, v2, v1` 按位域展开。

表 04-1　一条 vdot.vv 的位域展开

| 位域 | 值 | 含义 |
|---|---|---|
| `[31:26]` | `001110` | funct6 |
| `[25]` | `1` | vm，无掩码 |
| `[24:20]` | `00010` | vs2，示例中的 v2 |
| `[19:15]` | `00001` | vs1，示例中的 v1 |
| `[14:12]` | `010` | funct3，OPMVV |
| `[11:7]` | `00011` | vd，示例中的 v3 |
| `[6:0]` | `1010111` | opcode，OP-V |

表注：位域按 RISC-V 标准向量指令格式排布；值逐段来自 `design/SPEC.md:85-96`。

七段拼起来是 `0x3A20A1D7`。汇编的书写顺序是 vd、vs2、vs1，位域里 vs2 在 vs1 之上，两者不是同一个顺序。复核时用 Python 按位拼接算一遍，单次运行输出 `0x3a20a1d7`。编码校验脚本把三元组到机器码的换算列为自检项，同时要求规格文件正文命中同一个 funct6 与机器码。

## 4.6 编码为什么落在 funct6 001110

做法分两层。第一层按实现侧筛：把香山与 NEMU 的 OPMVV 译码表都扫一遍，两边都未占用、可作候选的 funct6 有 14 个；这次扫描在编码选定前完成，本指令接入后 001110 由本项目的译码表项占用。第二层按官方筛：实现侧空闲不等于官方未分配，所以再对 riscv-opcodes 快照 f24ac23 按字段扫描 funct3=010、opcode=0x57 的槽位，14 个候选逐个过一遍。两层的检查对象不同：实现侧看译码器能不能接，官方侧看这个编号有没有被标准或提案分配。

第二层筛完只剩 5 个：001110 与四个回退码。表 04-2 列出这 14 个候选的去向。

表 04-2　候选编码的占用情况

| 编码（funct6/funct3） | 占用者 | 状态 | 本项目 |
|---|---|---|---|
| `001100`/`010` | Zvbc 的 `vclmul.vv` | 已批准 | 弃用，原方案 |
| `001101`/`010` | Zvbc 的 `vclmulh.vv` | 已批准 | 弃用 |
| `001111`/`010`、`010101`/`010`、`010110`/`010`、`111110`/`010` | 未批准提案 rv_zvzip、rv_zvabd | 未批准 | 弃用 |
| `101000`/`010`、`101010`/`010`、`101100`/`010` | 未批准提案 rv_zvdot4a | 未批准 | 弃用 |
| `001110`/`010` | 无 | 快照内空闲 | 采用 |
| `010001`/`010`、`010011`/`010`、`101110`/`010`、`111001`/`010` | 无 | 快照内空闲 | 回退池，顺位替换 |
| `111111`/`010`、`101100`/`000`、`101100`/`001`、`101101`/`010` | vwmaccsu、vnsrl、vfmacc、vmacc | 已占用 | 禁用 |

表注：数据来自 2026-10-31 对 riscv-opcodes `f24ac23` 的字段级扫描，记录见 `stage2/2.1-design/encoding-gate-zvbc-2026-10-31.md:39-54`；该记录只覆盖这 14 个候选，末行四条是核对时撞上真实指令的编码，不进候选。

原方案是 funct6 `001100`（记录里称 C-enc1）。编码锁定前的复核报过「0 命中」，据此把它当成空闲码。2026-10-31 的复扫发现它归 Zvbc 的 `vclmul.vv`：旧脚本对 `14..12=2` 这种字段形式不命中，才漏判成空闲。同一次扫描里 `001101` 归 `vclmulh.vv`，这条也排除。复扫因此推翻了「0 命中」，编码改到 `001110`（C-enc1b）。

101100/010 是另一个陷阱。它是未批准提案 Zvdot4a 给 `vdot4a.vv` 的分配，语义是每 32 位元素取 4 个 int8 累加；本指令是单结果、不累加。语义不同不构成占用他人分配的正当理由，所以这条也排除。

四个回退码在快照里同样空闲，按 010001、010011、101110、111001 的顺位用，命中即弃。审查的实测结果：在工作区带快照运行 `python3 -I design/verify/encoding-gate.py --snapshot design/_recon/vendor/riscv-opcodes-f24ac23`，退出码 0。上游快照 141 个文件、1521 条指令行，与本编码重叠 0 条；SELF 归属 3 条，是本项目自己新增的译码表项，不算外部占用；阳性对照（旧码对 `vclmul.vv`、0x2C 对 `vdot4a.vv`）命中。

SELF 清单的匹配字段按条目而异：rocket-chip 的 BitPat 条目比对文件、条目名、32 位 pattern、mask 与 val；NEMU 表项比对文件、条目名与 32 位 pattern；VecDecoder 表项只比对文件、条目名与 funct6。同一条目第二次出现按冲突上报。不带快照运行时退出码 4，意思是官方归属这一层没有覆盖，不能据此说全空间无冲突。

这条结论有时间边界。它只说明截至 f24ac23 这个快照该槽位没有分配；上游以后若改分配，要用同一脚本重扫，编码可能落回回退池。主编码取 001110 而不是回退池首位的 010001，材料里没有留下单独的理由。能核的是记录里的扫描表按 funct6 数值升序列出这 14 个候选，001110（0x0E）是其中第一个空闲码；回退池的四个码同样按升序排列，是这条顺序上其后取到的四个空闲码。按顺位取首个空闲码，是能指认的规则，本章不另补理由。

## 4.7 官方规定与本项目决定的界线

表 04-3 把这一章的裁决按来源分开。分不清这两类，答辩时会把本项目的选择说成赛题要求。

表 04-3　官方规定与本项目决定

| 项 | 官方材料 | 本项目 |
|---|---|---|
| K=8 | 赛题伪代码 `for i in range(8)` | 采用 |
| 结果写 vd[0]、其余清零 | 赛题伪代码 `vd[1..VLEN-1]=0` | 采用，改写成位域 |
| 结果位宽 | 未写死，建议按 32 位写 | `vd[31:0]=sext32(S)` |
| 取哪 8 个字节 | 只写「各取 8 个 int8」 | 低 64 位 lane 0–7 |
| 内部位宽 | 未规定 | 19 位有符号 |
| `vl=0` | RVV 规定归约不写回 | 任意 `vl` 全写，偏离 |
| `vstart` | 未规定 | ≠0 判非法 |
| 编码 | 未分配 | `001110`/`010` |

表注：官方材料指赛题页与评分细则的伪代码（赛题评分细则第 24–37 行）与 RVV 规范；本项目列的依据在规格文件里逐条给出。

表 04-3 有两行要读清。结果位宽一行，赛题伪代码只建议 32 位，没有规定内部多宽；19 位是本项目按最坏和算出的下界，没有外部规范依据。`vl=0` 一行是本项目与 RVV 字面相反的地方，理由只有一个：赛题的伪代码循环不带 `vl` 条件。

这一章只覆盖 K=8、SEW=8、LMUL=1 这一条主线。K=16 不在主线：它需要 20 位，已有独立数据通路的综合结果，2 拍等价检查未成立（没有导入证明目标），尚未集成进 VIMacU，细节见第 10 章 §10.4–§10.5。两拍归约与写回旁路见第 5 章，译码表项与 NEMU 实现见第 6 章。本章的语义与编码是这两章的共同输入。
