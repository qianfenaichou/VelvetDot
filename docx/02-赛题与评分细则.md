## 一、赛题名称

**面向边缘 AI 大语言模型推理的 RISC-V 自定义 vdot 指令设计——基于“香山”昆明湖 V2 处理器架构**

- 目标平台：“香山”昆明湖 V2 处理器（国产开源高性能 RISC-V 处理器）
- 技术基础：具备成熟的向量扩展与自定义指令接口
- 核心要求：复用香山昆明湖 V2 现有的向量实现，将 vdot 指令作为向量指令集中新增的自定义指令进行功能单元扩展
- 指令语义：vdot.vv，SEW = 8，VLEN = 128

## 二、赛题背景

点积（Dot Product）是深度学习模型的核心计算内核，在推荐系统、大语言模型（LLM）等 AI 应用中通常占据总计算量的 60%–80%。在推荐系统中，78% 的个性化推荐将点积作为核心排序指标；在 Transformer 架构的 LLM 中，自注意力机制的矩阵乘法由海量点积构成，以 GPT-2 为例，点积占总计算量 70% 以上，其执行效率直接决定推理性能与能效，尤其在资源受限的边缘端更为关键。

RISC-V 凭借开源、模块化及可自定义扩展的优势，成为边缘 AI 处理器的主流架构。通过自定义向量点积指令（vdot），可在处理器流水线中集成专用硬件加速单元，以极小面积开销换取数倍点积吞吐提升，满足边缘 LLM 对高性能、低功耗、低成本的需求。

“香山”昆明湖 V2 作为国产高性能 RISC-V 处理器，具备成熟的向量扩展与自定义指令接口，为 vdot 指令的硬件集成提供了理想的架构基础。

## 三、vdot.vv 参考语义

```python
def vdot_vv(vs1, vs2, sew=8):
    # 根据SEW设定，从两个源向量寄存器中各取8个int8数据
    result = 0
    for i in range(8):
        result += sign_extend(vs1[i]) * sign_extend(vs2[i])
    # 结果写入目标向量寄存器vd的第一个元素
    vd[0] = result
    vd[1..VLEN-1] = 0  # 其他通道清零
```

官网原图：`attachments/vdot_semantics.png`

> 注意：官网伪代码没有明确 `vd[0]` 的位宽。SEW=8 时 `vd[0]` 只有 8 位，装不下 8 个 int8 乘积的和（最大 8×127×127=129032，至少需要 18 位有符号）。建议在设计文档中明确结果位宽与写入方式（例如按 32 位结果写入 vd 的最低 32 位，其余字节清零），并与 NEMU/RTL 保持一致；如组委会给出补充口径，以官方为准。

## 四、三个阶段

### 阶段一：环境部署（入门难度）

按照香山操作手册完成开发环境部署，输出验证信息与操作日志，并基于仿真波形分析向量加法指令的执行过程。

- 1.1 环境部署验证：输出 `hello xiangshan, I am xxx, IP address`（xxx 替换为团队或个人标识）
- 1.2 操作日志：完整的开发环境部署与操作过程日志
- 1.3 向量加法指令执行过程文档：依据仿真波形和参考文档，描述向量加法指令在香山中的执行过程

### 阶段二：设计与实现（中等难度）

根据 vdot.vv 指令语义（SEW=8，VLEN=128），完成设计文档和 RTL 实现，并基于香山仿真环境完成正数、负数、边界值三项基础功能测试。

- 2.1 vdot.vv 设计文档：包含指令语义、微架构设计、数据通路等完整设计说明
- 2.2 vdot.vv RTL 实现：Verilog/Chisel 代码，实现 vdot.vv 指令功能单元扩展
- 2.3.1 正数点积测试：基于香山仿真环境，验证正数输入的点积结果
- 2.3.2 负数点积测试：基于香山仿真环境，验证含负数输入的点积结果
- 2.3.3 边界值测试：基于香山仿真环境，验证边界值（如最大值、最小值、零等）的点积结果

### 阶段三：验证与优化（高难度）

为 NEMU 模拟器新增 vdot 指令，完成 RTL 与 NEMU 的协同仿真；用已有向量指令组合实现相同功能作为基线；对比基线组合与 vdot 专用加速单元的延迟，完成加速比分析。

- 3.1.1 NEMU 指令扩展：为 NEMU 模拟器新增 vdot.vv 指令支持
- 3.1.2 协同仿真验证：完成 NEMU 与 RTL 的协同仿真测试，确保一致性
- 3.2 基线功能实现：用 RISC-V 已有向量指令组合实现 vdot 相同功能（作为性能对比基线）
- 3.3 延迟加速分析报告：对比 Baseline（组合指令）与 vdot 加速单元的 latency 加速比分析

## 七、评分策略

- 85 分集中在“完整性 + 可行性”：三个阶段都做出可验证的交付物，比只打磨第二阶段更划算。
- 阶段三占 25 分，是单项最高；NEMU 扩展、协同仿真、基线、加速比报告四件事要齐。
- 可行性明确要求“复用香山现有向量实现”，设计文档要写清楚复用了哪些模块（VecDataSplitModule、Mgu、VecPipedFuncUnit、VIMac64b 等）。
- 探索性/创新性共 15 分，靠 latency、throughput、加速比等量化证据，以及向更高 SEW/VLEN 扩展的设计。
- 所有材料要可复现：命令、commit hash、配置、波形、日志、测试输入/输出。
