## 四、阶段一：环境与向量加法波形

1. 克隆并部署 xs-env：
   ```bash
   git clone https://github.com/OpenXiangShan/xs-env.git
   cd xs-env
   sudo -s ./setup-tools.sh
   source setup.sh
   source env.sh
   ```
2. 准备 XiangShan：将 `NOOP_HOME` 指向 kunminghu-v2 的 XiangShan 仓库；`make init`；`make emu CONFIG=MinimalConfig EMU_TRACE=1 -j$(nproc)`。首次编译约 1 小时。
3. 编译 Hello 程序：
   ```bash
   cd $AM_HOME/apps/hello
   make ARCH=riscv64-xs
   ```
   修改打印内容为 `hello xiangshan, I am <团队标识>, <本机 IP>`。
4. 运行并留证：
   ```bash
   ./build/emu -i $AM_HOME/apps/hello/build/hello-riscv64-xs.bin --no-diff
   ./build/emu -i $AM_HOME/apps/hello/build/hello-riscv64-xs.bin --diff ready-to-run/riscv64-nemu-interpreter-so
   ```
5. 写一个向量加法程序（`vsetivli` + `vle32.v` + `vadd.vv` + `vse32.v`），编译并在香山仿真中运行；打开 VCD/FST 波形，按“取指 → 译码 → 重命名 → 派发 → 发射 → 执行 → 写回”逐级截图。
6. 参考课程中的 vfadd 文档（744 行）组织阶段一文档。

## 五、阶段二：vdot.vv 的 RTL 实现

关键源码位置（kunminghu-v2，commit a4eeaabb）：

| 层次 | 文件 | 要做的事 |
|---|---|---|
| 指令编码 | `src/main/scala/xiangshan/backend/decode/Instructions.scala` | 新增 vdot.vv 的 32 位编码（opcode/funct3/funct6），避开现有 RVV 指令 |
| 向量译码 | `src/main/scala/xiangshan/backend/decode/VecDecoder.scala` | 新增译码表项，映射到 `FuType.vimac`（或新增 `FuType.vdot`）与对应 fuOpType |
| FU 类型 | `src/main/scala/xiangshan/backend/fu/FuType.scala` | 如需新 FU，新增类型并加入 `vecOPI`/`vecArith` 序列 |
| FU 配置 | `src/main/scala/xiangshan/backend/fu/FuConfig.scala` | 配置 latency、dataBits、读端口、issue 队列等 |
| 执行单元 | `src/main/scala/xiangshan/backend/fu/wrapper/VIMacU.scala` | 复用 VIMac64b 的乘法/累加能力，或新增 VDotU wrapper |
| 向量库 | `repos/YunSuan/src/main/scala/yunsuan/vector/vectorIMAC/` | 在 VIMac64b 中支持 8×int8 → int32 点积；新增 VimacType 操作码 |
| 数据拆分 | `backend/fu/vector/utils/VecDataSplitModule.scala` | 把 128 位向量拆成 8 个 int8 通道，送入乘法器 |
| 流水线 | `backend/fu/vector/VecPipedFuncUnit.scala` / `VecNonPipedFuncUnit.scala` | 选择流水/非流水实现；注意 latency 与 bypass |
| 测试 | nexus-am apps + XiangShan 仿真 | 正数、负数、边界值三组测试；用 `--diff` 与 NEMU 对比 |

实现提示：

- 香山现有向量归约指令（如 `vredsum.vs`）走 `FuType.vipu` + `VipuType.vredsum_vs`，可作为“结果写 vd[0]”的参考路径；向量乘加（`vmacc`/`vmul`）走 `FuType.vimac` + `VimacType`，可作为“8 个 int8 乘加”的参考路径。两条路径都可以复用。
- 若复用 `VIMac64b`：它按 64 位 lane 工作，需要把 8 个 int8 打包进 lane，做符号扩展后相乘并累加；注意 8 位乘法的符号扩展、32 位累加位宽、以及结果只写 vd[0] 的约束。
- 若新增专用 `VDotU`：8 个乘法器 + 加法树，面积小、延迟低；可用 `VecPipedFuncUnit` 做 2–3 级流水，并在 `FuConfig` 中声明 latency。
- 无论哪种方案，都要在设计中明确：`vl` 的处理、`vstart` 的处理、`vm` 掩码、tail 元素清零、SEW/VLEN 参数化。
- 测试程序建议用内联汇编构造输入，C 代码计算参考结果，打印 vdot 结果与期望值；边界值覆盖 int8 的 -128、127、0，以及累加溢出（8×127×127=129032，超过 int16，验证 32 位累加）。

## 六、阶段三：NEMU 扩展、协同仿真与性能分析

| 任务 | 文件 / 工具 | 要点 |
|---|---|---|
| NEMU 译码 | `NEMU/src/isa/riscv64/instr/rvv/decode.h` | 用 `def_INSTR_TAB` 增加 vdot.vv 的匹配模式；确保与 RTL 编码一致 |
| NEMU 执行 | `NEMU/src/isa/riscv64/instr/rvv/vcompute.h` + `vcompute_impl.c` | 在 `vcompute.h` 增加 `def_EHelper(vdot)`，在 `vcompute_impl.c` 复用/新增 8 个 int8 符号扩展乘加宏；写 vd[0]，其余清零 |
| NEMU 挂接 | `NEMU/src/isa/riscv64/instr/rvv/decode.h` + `vreg.h` | `decode.h` 增加匹配模式；确认向量寄存器写回、vstart/vl 处理 |
| 协同仿真 | XiangShan `--diff` + 新 NEMU 参考库 | 编译 NEMU 为 `riscv64-nemu-interpreter-so`，替换 ready-to-run 中的参考库 |
| 基线 | RVV 组合指令 | 用 `vwmul.vv` + `vwredsum.vs`（或 `vmul` + `vredsum`）实现等价功能；注意 8 位溢出，优先用 widening |
| 性能分析 | 波形 / 性能计数器 / perf | 测 latency（每条 vdot 的周期数）、throughput（每 N 周期一条）、加速比 |

基线建议：

- 基线 A（推荐）：`vle8.v` 加载两个 8 元素向量 → `vwmul.vv` 做 8→16 位宽乘法 → `vwredsum.vs` 做宽化归约 → 结果写标量/向量；功能正确，且全部是现有 RVV 指令。
- 基线 B：`vmul.vv` + `vredsum.vs`，但 8 位乘法和累加会溢出，必须证明输入范围不会溢出，或在报告中说明局限。
- 基线 C：标量 8 次乘加，作为“无向量加速”的对照。

性能指标：

- `latency`：从指令发射到写回 vd[0] 的周期数；分别统计 vdot 与 baseline 的关键路径。
- `throughput`：连续发射相同指令时的平均间隔（CPI）；可用循环跑 1000 次取平均。
- `speedup = baseline_latency / vdot_latency`；同时给出面积/资源占用的定性分析。
- 如果条件允许，用 XiangShan 的性能计数器或 perf 采集指令数、周期数、停顿原因。
