# 03 · 香山赛道提交操作指南（官网系统 + XiangShanLab）

## 一、三条提交链路

| 链路 | 提交内容 | 位置 |
|---|---|---|
| 大赛官网系统 | 阶段一执行日志/过程文档；阶段二设计文档和基础测试文档；阶段三协同仿真和性能分析文档 | 个人中心 → 我的参赛 → 预赛 → 更新项目 → 文档提交位置 |
| 大赛官网系统 | 阶段一操作录屏；阶段二解题思路录屏；阶段三波形仿真和性能分析录屏 | 系统的视频提交位置 |
| 大赛官网系统 | 参赛方代码仓库地址 | 大赛官网系统的相应位置 |
| XiangShanLab | 加密后的提交信息 `submission.asc` | Fork 后提交到 `01_参赛选手提交区/<团队名称>/`，再发起 PR |

> 官网系统和 XiangShanLab 两条链路都要完成。

## 二、官网报名与提交

1. 打开 https://rv.cie.org.cn/home，右上角“注册/登录”，选择“中国电子学会用户登录”。
2. 完善资料：在校生填写学校名称、学信网截图、指导老师；非在校生填写单位名称、身份证、信用中国信息。
3. 创建或加入团队：个人团队或单位团队；队长负责报名。
4. 首页“赛事内容” → “RISC-V 高水平应用方向” → “CIE-香山社区” → 赛题详情 → “立即报名”。
5. 个人中心 → 我的参赛 → 切换“预赛” → “更新项目” → 上传材料（红星必填）。
6. 每个阶段以最后一次成功提交的资料为准。

## 三、XiangShanLab 提交流程

官方指南：https://github.com/OpenXiangShan/XiangShanLab/blob/master/2026-CIE-RISC-V-Contest-Application-Track/SUBMISSION_GUIDE.md

1. Fork https://github.com/OpenXiangShan/XiangShanLab 到自己的账号。
2. 克隆自己 Fork 的仓库，进入 `XiangShanLab/2026-CIE-RISC-V-Contest-Application-Track`。
3. 在 GitHub 创建作品公有仓库，命名建议 `cie2026-团队名称-作品名`。
4. 把代码、设计文档、测试、报告推到该公有仓库。
5. 在本目录创建 `my_submission.txt`：

```text
team-name: 您的团队名称
repo-url: https://github.com/您的用户名/您的公有仓库.git
github-username: 您的GitHub用户名
contact-email: 您的邮箱@example.com
project-description: 简要描述您的项目，不超过100字

# 可选信息
team-members: 成员1(角色), 成员2(角色)
university: 您的学校/单位
advisor: 指导老师
phone: 联系电话
notes: 其他需要说明的事项
```

6. 运行 `source ./submit.sh my_submission.txt`。脚本会导入 `contest/public-key.asc`，用 GPG 加密 `my_submission.txt`，生成 `01_参赛选手提交区/<团队名称>/submission.asc`。
7. `git add . && git commit -m "提交2026CIE大赛作品：<团队名称>" && git push`。
8. 发起 Pull Request：base 选 `OpenXiangShan/XiangShanLab`，head 选你的 Fork；标题 `[2026CIE大赛] 团队名称 - 项目名称`。
9. 按 PR 模板填写团队信息、阶段完成情况、提交内容概述。

## 五、注意事项

- GPG 收件人：`3502918558@qq.com`；公钥指纹 `936E3DCCFEB2C1C1472BD43E11489B37147B12E1`。
- 如果 GPG 未安装：Ubuntu `sudo apt install gnupg`；macOS `brew install gnupg`。
- 只提交加密后的 `submission.asc`；不要把 `my_submission.txt` 明文、手机号、邮箱等个人信息提交到公开仓库。
- `SUBMISSION_GUIDE` 写 PR base 为 `main`，但仓库默认分支是 `master`；以页面实际默认分支为准。
- `SUBMISSION_GUIDE` 要求作品仓库为 public，但其 `my_submission.txt` 模板示例写的是“私有仓库”；建议以 public 为准并向组委会确认。
- 团队名称会作为目录名，避免 `/`、空格、特殊字符；建议用英文/数字/下划线。
- 官方原文说“加密后的代码仓库”，实际加密的是 `my_submission.txt`（含 repo-url），不是整个代码仓库。
